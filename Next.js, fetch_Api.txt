Absolutely. In Next.js, fetch() is one of the most common ways to call APIs. The important thing to understand is that Next.js supports both Server Components and Client Components, so fetch() can be used differently in each.

Below is a complete beginner-friendly example.

1. What is fetch()?

fetch() is a JavaScript API used to send HTTP requests.

For example:

fetch("https://api.example.com/users")

It can perform:

GET → retrieve data
POST → create data
PUT → update data
PATCH → partially update data
DELETE → delete data

The basic flow is:

Next.js Component
       |
       | fetch()
       ↓
     API
       |
       ↓
    Response
       |
       ↓
 response.json()
       |
       ↓
    JavaScript
       |
       ↓
     UI

4. How does this code work?

Let's understand this line:

const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
);

fetch() sends an HTTP request.

Conceptually:

Next.js
   |
   | GET /users
   ↓
JSONPlaceholder
   |
   | HTTP Response
   ↓
response

The response object is not yet the JavaScript array.

We need:

const users = await response.json();

Now the JSON response becomes JavaScript data.

For example:

[
    {
        "id": 1,
        "name": "Leanne Graham",
        "email": "leanne@example.com"
    },
    {
        "id": 2,
        "name": "Ervin Howell",
        "email": "ervin@example.com"
    }
]

After:

const users = await response.json();

you can use:

users.map(...)
5. Why do we use async and await?

This is very important.

Network requests take time.

For example:

fetch()
   |
   |---- waiting for server ----|
                                |
                              response

JavaScript doesn't want to block everything while waiting.

fetch() returns a Promise.

Example:

const response = fetch(url);

At this point:

response = Promise

Using:

await fetch(url)

means:

wait for fetch() to complete
             ↓
        get response

So:

const response = await fetch(url);

Then:

const users = await response.json();

There are actually two asynchronous operations:

fetch()
   ↓
HTTP Response
   ↓
response.json()
   ↓
JavaScript object/array

14. Client Component + fetch()

Now an important Next.js concept.

Suppose you want a button:

Click Button
     ↓
fetch()
     ↓
API
     ↓
Display result

For this, we normally use a Client Component.

Create:

app/client-users/page.js
"use client";

import { useState } from "react";

export default function ClientUsers() {

    const [users, setUsers] = useState([]);

    const getUsers = async () => {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
        );

        const data = await response.json();

        setUsers(data);
    };

    return (
        <div>

            <h1>Users</h1>

            <button onClick={getUsers}>
                Load Users
            </button>

            {users.map((user) => (
                <div key={user.id}>
                    <h3>{user.name}</h3>
                    <p>{user.email}</p>
                </div>
            ))}

        </div>
    );
}

Here:

"use client";

tells Next.js that this component should run on the client.

This is useful when you need:

useState
useEffect
button click handlers
browser APIs
interactive UI

16. Loading state

A real application should display something while waiting.

"use client";

import { useEffect, useState } from "react";

export default function Users() {

    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {

        const loadUsers = async () => {

            try {

                const response = await fetch(
                    "https://jsonplaceholder.typicode.com/users"
                );

                if (!response.ok) {
                    throw new Error("API error");
                }

                const data = await response.json();

                setUsers(data);

            } catch (error) {

                console.log(error);

            } finally {

                setLoading(false);

            }
        };

        loadUsers();

    }, []);

    if (loading) {
        return <h2>Loading...</h2>;
    }

    return (
        <div>

            <h1>Users</h1>

            {users.map((user) => (
                <div key={user.id}>
                    <h3>{user.name}</h3>
                    <p>{user.email}</p>
                </div>
            ))}

        </div>
    );
}
17. Error handling

A good fetch() implementation should use try/catch.

try {

    const response = await fetch(
        "https://jsonplaceholder.typicode.com/users"
    );

    if (!response.ok) {
        throw new Error(
            `HTTP Error: ${response.status}`
        );
    }

    const data = await response.json();

    console.log(data);

} catch (error) {

    console.error("Error:", error);

}

For example:

200 → Success
201 → Created
400 → Bad Request
401 → Unauthorized
403 → Forbidden
404 → Not Found
500 → Server Error
